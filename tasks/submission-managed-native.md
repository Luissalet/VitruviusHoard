# Retained managed/native inputs

Task1253 repairs the admission gaps reproduced by research1250. `managed.verify_native` accepts finished or imported managed boundaries and native function jobs without reopening originals or native sessions. The prior job-input path remains available. Supplied saved Evidence can instead enter through `query.native_observations`, or accompany selected native jobs. The maintained verification/matching/schema helpers are unchanged.

Each job document is reauthenticated before conversion. Its complete bytes and SHA, recorded provider/profile/revision where available, and artifact binding are retained separately from the current derived historical carrier and local occurrence IDs. Known session/project/artifact/profile contradictions are rejected; missing historical profile remains unknown. Multiple occurrences of the same native document/context can group their job IDs, preserving their shared observation rather than fabricating extra evidence.

Supplied Evidence is parsed and its full value and serialization hash are kept. Semantic IDs omit module display labels; the complete value binds the received labels to this receipt without authenticating their truth. Duplicate supplied IDs, including values with changed module labels, and duplicates between supplied and generated inputs fail explicitly. Source observations resolve direct result citations and list absent transitive Evidence links as unresolved. Imports preserve the opaque supplied values, including literal strings named job_id/session_id/artifact_id, while exterior project links still remap.

The verifier receives jobs first and supplied values second, each in caller order. The existing exact/decorated/module-unknown/first-tie rules and all candidates remain visible. Complete-within-inputs stays separate from declared export coverage. Unknown modules, empty partial exports, unsupported operations and invalid supported payloads remain distinct. A container/header result is not a native export inventory. No CLR call, loader resolution, executable equivalence or token-to-native-address mapping is inferred.

Validation is based on original compiled C#/PE fixtures with real Ghidra dossiers and closed sessions, plus an original thin Mach-O compiled by Zig. Go's symbol table and LLVM's actual export trie corroborate names, addresses and weak-def flags; a local function is present in symbols and absent from exports. Two authored functions and linker-generated exports are retained. Input constructors use the incorporated Evidence builder only to encode those observations; source expectations come from the authored programs and independent readers, not the verifier. Targets are not executed.

The latest area run passed44 tests without failures/errors/skips:33 new retained/native cases, the existing real native verification case, and10 evidence/import regressions. It covers fresh compositions after two transfers without originals, full source payload preservation, an original-path availability trap, exact/decorated/no-mangle matches, combined conflicts and order-dependent ties, unknown/empty/unsupported inputs, invalid hashes/schemas, duplicate IDs across both forms, literal-ID opacity, corruption of all selected documents, and project/state/operation/profile guards. Missing profile is explicitly tested without connecting to a session. Every pytest used the mandatory wrapper and a new basetemp with cache/bytecode disabled.

Earlier failures remain preserved: the original imported-input RED rejection; a first implementation error where an intermediate schema stripped artifact fields; and the separate opaque-import RED that remapped literal caller values. The schema now preserves complete source values and import changes only this operation's supplied Evidence input.

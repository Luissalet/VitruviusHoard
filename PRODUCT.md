# Vitruvius product context

Vitruvius is the local frontend-design workbench in the Hoard family. It serves people and assistants working through native API/MCP and the common Faustus panel. It combines a criterion library, reference gallery, editable HTML and motion studies, browser rendering, lint/critique, tokens, diagrams and now complete application-source projects. Planning/model calls use the configured global Sparks; creating and running the original source starters needs no model.

The Applications surface extends the existing Operate interface. Its task is create a source project, edit files, start an actual local preview, inspect a render and export independent source, while retaining data and earlier source revisions. Preserve existing navigation, components, theme, language switch and copilot. Source files and ordinary local application behavior lead the work; no new marketing identity or feature slogans.

Implement selected capabilities from reference projects as native code, independent of their names, APIs and future compatibility. Farm.js is research evidence; its CLI, MCP and repository are not product dependencies. Original project sources remain editable, and the output uses Python standard library with HTML/CSS/JavaScript and generated type declarations. Claims are limited to tested workflows; do not claim universal compiler, renderer or cloud parity.

The software workspace incorporates complete public Babel and the existing Theseus engines/editors as native code. Three modules and automation start OFF. A visible owner application project/revision relates explicit environments, artifacts and retained results with distinct native hashes. Theseus development remains incomplete and paused due to usage limits; this task preserves capabilities rather than developing its pending scope. Root owns CUA, installed-package/live acceptance and real migration after review.

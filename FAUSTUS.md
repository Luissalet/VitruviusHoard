The Critique screen shows all of it. Attribution of the studied rule sets is in NOTICE.

Slop audit (radar 03-11-2026): `design_slop_audit` renders a page at 8 widths (320-1920), runs core, slop, unslop (24 computed-style sign rules after unslop by Damir Sokolovsky, CC BY 4.0), craft and quality, scores slop 0-100 and picks a mode: heavy = ordered fix passes (spacing, color, icons, copy, type, layout, details, visuals, motion), light = polish list, none = leave it. Findings carry boxes and widths; the Critique screen marks them on the screenshot. `design_direction_brief` writes Product / Character / Bright moment / Signature / Avoid with the family model (theme-catalogue fallback).
Language (03-11-2026): `design_slop_audit`, `design_direction_brief` and `design_rules_list` take `lang` (`es` default, `en`); REST (`/api/slop-audit`, `/api/direction-brief`, `/api/rules`) also reads `lang` or Accept-Language. English stays the source and is what audits store on disk; `vitruvius_hoard/i18n_es.py` holds the Spanish (Spain) table keyed by rule id (name, description, fix for all 168 rules), the 9 pass titles, mode summaries and the unslop credit (CC BY, both languages); `GET /api/slop-audit/<id>?lang=` re-reads a stored audit in either language without auditing again. Measured sentences are built in code from English fragments, so in Spanish a finding's detail is the rule's Spanish description plus the counts and widths found. The Critique screen passes its UI language to the audit, the brief and the rules list and re-renders a shown audit when the language is switched. Tests: `tests/test_i18n.py` (every rule id has Spanish text, no English function words in the table, lang plumbing).

Design rules (#1694): the lint is a registry of 168 rules as data (`design_rules_list`; engines static, browser and visual; packs core, slop, quality, craft, unslop and ds). `design_critique` returns Floor/Reflex/Finish tiers and a gate, accepts validated waivers for Reflex findings (24+ characters, never repeated) and can run a clean-context review with only screenshots, HTML and findings (first word recapture, rebuild, fix or ship). With `tokens_id` the ds rules compare a page with a saved design system. `tokens_generate` and `design_brief` deal themes with memory of the last three builds and reproducible seeds (`theme_deal`, `theme_check`, `theme_memory`, `theme_list`). `page_check` with `before`/`kept` fails a redesign that loses links, fields, handlers or titles (`page_kept`). The Critique screen shows all of it. Attribution of the studied rule sets is in NOTICE.

Slop audit (radar 03-11-2026): `design_slop_audit` renders a page at 8 widths (320-1920), runs core, slop, unslop (24 computed-style sign rules after unslop by Damir Sokolovsky, CC BY 4.0), craft and quality, scores slop 0-100 and picks a mode: heavy = ordered fix passes (spacing, color, icons, copy, type, layout, details, visuals, motion), light = polish list, none = leave it. Findings carry boxes and widths; the Critique screen marks them on the screenshot. `design_direction_brief` writes Product / Character / Bright moment / Signature / Avoid with the family model (theme-catalogue fallback).
Language (03-11-2026): `design_slop_audit`, `design_direction_brief` and `design_rules_list` take `lang` (`es` default, `en`); REST (`/api/slop-audit`, `/api/direction-brief`, `/api/rules`) also reads `lang` or Accept-Language. English stays the source and is what audits store on disk; `vitruvius_hoard/i18n_es.py` holds the Spanish (Spain) table keyed by rule id (name, description, fix for all 168 rules), the 9 pass titles, mode summaries and the unslop credit (CC BY, both languages); `GET /api/slop-audit/<id>?lang=` re-reads a stored audit in either language without auditing again. Measured sentences are built in code from English fragments, so in Spanish a finding's detail is the rule's Spanish description plus the counts and widths found. The Critique screen passes its UI language to the audit, the brief and the rules list and re-renders a shown audit when the language is switched. Tests: `tests/test_i18n.py` (every rule id has Spanish text, no English function words in the table, lang plumbing).

Sound in motion (#1691): a composition carries `{t, rol}` events and a style (`motion_sound_plan` read-only, `motion_sound_render`, `motion_render` with `audio`). Effects come from the procedural bank and kit of an MIT library (earshot, optional `[sound]` extra, no models); each is placed by its measured onset or peak and the mix is brought to -14 LUFS / -1 dBTP with soft saturation and a limiter, reporting `reached` honestly. The MP4 carries AAC 48 kHz stereo; the HTML export is silent. Verified by ffprobe, ebur128 and by decoding the MP4 audio (offset under 1 ms on isolated cues) and through the Motion screen.

Visual parity (Ágora #2345): `visual_parity`, `visual_parity_get`, `visual_parity_list` and `visual_parity_delete` (REST `/api/parity*`, Parity screen) compare a candidate page with a reference (URL, inline HTML or render id) at 1440 and 390 px by default. Both load with the clock, random numbers, frames, transitions, animations and videos frozen and lazy content fired by scrolling; the reference loads twice and the pixels that differ between loads are masked as noise. Each viewport-high screen (up to 12) passes with 98 % of stable pixels within 10 % per channel; total height within 4 px; all thresholds configurable. Output: score and pass/fail per width and screen, a global verdict or the list of failures, diff images (red different, blue noise, rest dimmed) and a side-by-side page with a slider (`GET /api/parity/{id}/report`). Runs live in `data/design/parity/<id>/`. `render_compare` is unchanged. Tools 102 to 105 of design.

Remake (Ágora #2399): `remake_start`, `remake_get`, `remake_list`, `remake_code`, `remake_continue`, `remake_stop`, `remake_delete` (REST `/api/remake*`, Remake screen) remake a public page from its URL or a full-page screenshot until visual parity. Reference loaded frozen at 1440 and 390 px (twice each for the noise mask) with its layout, palette, fonts, links, forms and every stylesheet, image, font and plain video it loaded; bot-check pages and sign-in or payment pages are refused. First candidate: `copy` (rendered page as a static snapshot with its own CSS and files in `assets/`, no trackers or scripts, noindex) or `rebuild` (new HTML/CSS from the global model through Faustus). Each round is scored screen by screen against the cached reference (also stored as a parity run); repairs fetch missing files first, then send the first failing screen of each width to the model with element-by-element differences, pictures and the code (copy: CSS appended last; rebuild: SEARCH/REPLACE edits or a whole file); worse rounds are undone; unreachable model retried up to four minutes. Output in `data/design/remake/<id>/`: `site/`, `rounds/<n>/`, `assets.json` (origin and licence per file), `slots.json` (what still belongs to the original) and a ZIP with `paridad.json` and `creditos.md`. ## Skills for the agents that connect

This app carries procedures from the skill library of the family's workspace for the agents that connect to it: vitruvius: `hoard-design-loop`, `product-ui-visual-direction`, `unslop-interface`, `hallmark-page-design`, `web-accessibility-design`, `elephant-goldfish-design`, `panel-builder`, `diagram-authoring`, `documentation-lookup`, `reverse-engineering-workflow`, `code-impact-analysis`; babel: `documentation-lookup`, `code-impact-analysis`, `learn-this-repo`; theseus: `reverse-engineering-workflow`, `code-impact-analysis`, `legacy-web-app-onboarding`. They are named in what an agent reads on connecting, read with `skills_list` and `skill_read`, searched and assigned with `skills_library` and `skills_assign`, and offered as prompts. The person chooses them on the skills page (`/api/agent/skills/page`) or in the hub's Skills tab; the `skills` block of `faustus-plugin.json` holds what the app asks for by default.

## Project workflow

1. Enable Design and create/select a native application-source project. Its files, source SHA256 and source revisions remain editable through the original editor and standalone exporter.
2. Enable APIs and associate an explicit existing or newly registered environment with that revision. Several environments may belong to one project. Check a chosen file with the associated environment. Findings and native result metadata retain the selected environment, file digest and exact source revision; a new revision needs its own association.
3. Enable Reverse Engineering and associate one file, or select '.' for the complete recorded source tree. The association creates or uses a real native Theseus project/artifact. The native directory digest is retained separately from Vitruvius's JSON source digest. Changed source bytes cannot silently inherit an old revision label.
4. Request an existing native analysis, then read and retain its result. The real job, artifact ID, source identity and original analysis-file SHA are checked. A complete retained analysis document is saved with its metadata. Results remain readable from the root with modules OFF and continue identifying their old source revision after edits. The native Theseus editor provides findings, scenarios, comparisons, sessions, records, portable evidence and explicit reader/builder handoffs; the common flow does not automatically disclose reader evidence to a builder.

Existing design library/search, references/collections/patterns, HTML rendering, lint/critique, tokens/playground, motion, diagrams/isometric diagrams, source applications, data/actions and standalone exports remain available. Existing Babel indexing, version-exact lookup/checking, docs/docsets/locales and Ask the docs remain available. No old source repository, server, iframe or launcher proxy is required.

## Lifecycle and models

Cold HTTP/stdio discovery returns110 schemas without native factories, stores, recovery, models or workers. Native lifetimes are in-process and independently owned. Browser/ingest/dense jobs begin under explicit use or the opted-in native automatic setting. Babel's indexing worker is lazy and drains on OFF. OFF waits native readers, admitted writes, background owners and async finally before closing pools/clients/stores. One stopped or held module does not prevent using another. Sent mutations without a complete response are classified outcome_unknown; reconcile native state before retrying.

All LLM work uses only the exact global Sparks selection via Faustus938: first configured Faustus, endpoint_id/model/connection_revision pinned for the job, fixed global-model chat path, family bearer and original response schema/effort. Parallel consumers share one descriptor future; jobs remain independent. Provider keys stay in Faustus. There is no local text fallback, alternative model, model load, HTTP retry or schema relaxation; incomplete/truncated completion fails. Non-text rendering, embeddings and optional native analysis remain independent capabilities. Live LLM acceptance requires the deployed938 contract and a separately coordinated trial.

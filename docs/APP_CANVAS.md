# App preview canvas

In **Applications**, open a project and choose **Open preview**. The preview runs on its own loopback origin and keeps the same address when the project switches revisions. Links, stylesheets and record actions use the project's own routes. Opening the preview in another tab is still available.

- `app_project_canvas_view(id, scope?, max_chars?, actor?)` reads the displayed page or current viewport and returns control references.
- `app_project_canvas_act(id, action, args, actor?, target?)` supports `click`, `fill`, `select`, `navigate`, `scroll`, `highlight` and `wait`. It uses the App Dock arguments for that action. Send `actor: {id, name, color}` to identify the cursor. To point out part of a page, call `highlight` with a `ref` or `text` and an optional `note`.
- For `click`, `fill` and `select`, the cursor travels to the control and pulses before the action. The control is outlined after the action. Use `args.ref`, `args.text` or `args.label` to locate it. You can also supply `target` with a CSS `selector` or a `vsrc` from the current preview. A document-relative `box` with `x`, `y`, `w` and `h` can distinguish repeated source positions. Reduced motion keeps the outline and skips the cursor. Edit presence expires after four seconds of inactivity.
- The app uses the same cursor for reads, actions and source edits. When a call identifies the caller, the project remembers the caller's explicit actor for later calls. The caller ID supplies the default name and a stable color. Each caller without a declared color gets an unused color in the project while the palette has room. An explicit name or color carries through to the next edit even when it omits actor. Both tools need one Applications tab hosting the project's preview. They report when it is absent or when multiple tabs are hosting it. Preview actions go through the project's own controls. Source revisions and `app_project_undo` are managed by the [application project workflow](APP_PROJECTS.md).

The dedicated **Canvas** places Navigate, Select and Comment together in its toolbar. Elements in the inspector select and bring into view the corresponding node from the active document. Alt+Shift+S and Alt+Shift+C switch modes, and the toolbar and element list also support arrow keys, Home and End. Comments keep their original anchors, report missing anchors and can be resolved, reopened or undone by the person. The source history shows each recorded transition, author and time. Undo checks that the current revision and its update timestamp still match and restores the preceding saved source. Older revisions without attribution remain visible and the person can explicitly restore the prior saved version. In-place updates keep the preview document open when its source change can be safely patched. Other source changes load the replacement frame before switching to it.

Vitruvius owns the reverse proxy and starts a separate copy of the source runtime for each displayed revision. The current runtime stays available until its successor is ready. The proxy adds the shared App Dock bridge and any installed scripts listed in `app_preview.PREVIEW_SCRIPTS` to HTML. A response exposes its actual revision through `X-Vitruvius-Revision` and the `vitruvius-preview-revision` meta tag. It also names the opening of the preview (one per proxy, unchanged by revision refreshes) through `X-Vitruvius-Session` and the `vitruvius-preview-session` meta tag; `app_project_preview` status carries it as `session`. The script list affects served previews. The source files, standalone runtime and export ZIP preserve the project's own content.

When Vitruvius is docked, the outer App Dock continues to address the Vitruvius page. **Applications** hosts the preview in an inner frame with `referrerPolicy="origin"`. The inner handshake and calls use the existing `dock/hello`, `dock/ready`, `dock/call` and `dock/result` messages. Each host checks its own frame's window and origin. A project-specific event stream connects the Applications page to the canvas tools without opening a tab.

The browser includes its displayed revision in the canvas stream request. This gives consecutive agent edits a short window to let the previous revision reach the visible frame. The inner host relays `canvas/presence {id, actor, revision, target, expires_at}` for source edits on the same stream as tool calls. The preview checks its served revision before using the target's `vsrc`, `selector`, inferred `sources` or `box`. It measures the element in the live document when it can resolve one. It acknowledges through `dock/result` after the pulse starts, or immediately when reduced motion is enabled. The committed revision still arrives on the revision stream. A mutating `dock/call` may carry `presence` with locator hints for the same cursor and outline behavior.

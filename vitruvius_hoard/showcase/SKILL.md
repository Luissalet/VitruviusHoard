# Showcase recipes

## When to Use

Choose a concrete working reference when the brief asks for a cinematic or spatial showcase. Search `showcase_recipes` in Spanish or English, then read `showcase_recipe` with its id. The returned pair includes observed source frames, decisions, reproduction prompt, implementation and checkpoints.

## Procedure

1. Read the chosen recipe and its complete source with `showcase_source` or download the independent ZIP. Open its reference URL and inspect the named interaction states.
2. Preserve the recipe's light, pacing, type and interaction constraints while replacing its clearly marked demonstration content. Each recipe supplies its own agent skill.
3. Serve the exported folder with `python -m http.server 8080`, then open its id/index.html entry. Fonts, portrait and rendering engine ship locally.
4. Use `showcase_remake` after explicitly enabling Design to create a retained Rehacer run. Its default copy round measures the stable opening composition at 1440 and 390 px. Use rebuild for a model-authored reconstruction through the configured global model.
5. Read the retained run with `remake_get`. Inspect each named interaction state separately and repeat visual parity with the same camera, scroll, pointer and selected project.

## Pitfalls

A stable screenshot score covers that composition. Verify page turning, pointer reaction, walking, navigation and scrolling through their normal controls. Source reel frames are reference evidence with their original rights. Exported code, stock portrait, fonts and rendering engine have their own provenance. The portrait subject and example works are demonstration content.

## Verification

Use the recipe checkpoints at desktop and mobile sizes. Test keyboard, touch, reduced motion and WebGL fallback. Record the source revision, viewport, state, reference URL, retained parity id and actual scores. Report remaining defects concretely.
